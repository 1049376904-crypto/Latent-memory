# Latent · 显影

**让 AI 跨会话记得你。**

不是这次对话记得——是换了新窗口、过了一个月、甚至换了个客户端之后，还认得你是谁、记得你们之间发生过什么。

---

## 名字的来历

「潜影」是摄影里的术语：胶片曝光之后、显影液处理之前，影像其实已经在那儿了，只是还看不见。要经过显影，它才显出来。

这对应了这个项目的核心判断：**人格不是凭空造出来的，是一直潜在那儿，靠真实相处显影**。所以这套工具不负责“设计”一个 AI 人格，只负责把已经发生过的东西显出来、留住、并且在下一次对话时送到该在的地方。

也因此只进不退——显出来的影像不会自己褪回空白。

---

## 它解决什么问题

你和 AI 聊了几个月，攒下很多东西：一个只有你们懂的称呼、一次它拒绝你但你反而更信任它的对话、一个说好了要一起做的事。

然后你开了个新窗口，这些全没了。

现成的方案要么是“把所有历史塞进上下文”（贵、慢、而且模型读不动），要么是“让 AI 自己总结几句”（总结出来的是评语，不是记忆）。

这个项目的做法是分三层：

| 层 | 内容 | 加载方式 |
|---|---|---|
| **人格文件** | 不变量：你是谁、相处原则、里程碑索引、检索约定 | 常驻上下文，每次全量加载 |
| **记忆库** | 正文：发生过什么的完整叙述 | 按需检索注入 |
| **会话线索** | 上次聊到哪、当下什么状态、有什么没聊完 | 换窗时召回 |

分错层是这套东西最容易垮掉的地方——人格文件变成流水账，或者记忆库里找不到情感重量，都源于分层没守住。

## 怎么开始

**如果你不想读技术文档**：把这个仓库交给一个**能读文件、能跑命令的 AI**（Claude Code、Codex 这类），说一句：

> 读一下 `docs/给AI的引导指南.md`，带我做。

那份文档是**专门写给 AI 读的**，它会一步步带你走完，包括问清楚你的情况、帮你答问卷、生成文件、接入客户端。

**如果你已经有一份人格文件**：初始化时用 `--persona <你的文件>` 带上它，再按自己的情况
选一条。① **编译增强**：它是最高优先级来源，原文逐字认领，语料只补缺口；工具把内容归入
十二节，真要删改会连 diff 与理由交给你逐节确认。② **原文件直接使用**：显式选择
`--existing-persona-choice use_original_as_is`，正文不拆块、不重排，只给出货副本追加标准记忆
协议，再走 route 与 ship。两条都是用户选择，没有隐藏优先级；第二条跳过三项编译检查，
**跳过不等于通过**。完整三步命令见《快速上手》“已有成熟人格，只想接记忆服务？”。

## 几条贯穿全项目的设计判断

这些不是实现细节，是这套东西为什么长这样：

**纪录片，不做说服。** 写发生过什么、当时说了什么原话、现在什么状态；不写“你应该温柔”这类判断句。形容词长不出人格，只会长出一个会背评语的模型。

**顺序即权重。** 长上下文里模型对开头和结尾的注意力显著高于中段（lost-in-the-middle），所以最重的两样东西放两头，中间放可展开的细节。人格文件的节序本身是设计的一部分。

**用进，不废退。** 被检索命中的记忆权重上升；没被命中的原地不动，**不做时间衰减**。这是刻意的产品判断——记忆不该因为“最近没被聊到”就贬值，那会让人感受到“AI 在忘记我”。

**病灶迁移。** 每段记录必须以“这件事现在的状态”收尾。少了它，未来重读时会把“最后读到的内容”误当成“正在发生的事”。这条在代码里是强制的，不是建议。

**宁可短且真，不可长而空。** 用户答不上来是有效信息。新用户第一天没有隐喻、没有里程碑，硬要就是逼人现编——那比空着更糟。

**知道该查 vs 查得到。** 真机实测发现：光有检索工具，模型根本不会主动去查。所以人格文件负责“知道该查”，MCP server 负责“查得到”，缺哪半都不成立。

**拦得住，还要给得出出路。** 出货前的每一道闸，报错里都带着下一步该敲哪条命令、抄哪个字段——**判据是「把那行报错原样交给一个没读过本项目的 AI，它必须给出正确的下一步」**。这不是文案讲究：闸门判得对、也确实拦住了，但只说“哪儿不合格”不说“怎么才算合格”，人就会自己找路绕过去（真实案例是手动 `cp` 预览文件出货，连带跳过了他下一步正要验的那道检查，全程零报错）。同一条规矩的另一面是**不给 `--force`**——这次的问题是出口没写，不是闸太严。

## 技术形态

- **零依赖**：BM25 检索层、RRF 融合、用进废退、时间戳解析、MCP 协议实现全是 Python 标准库。只有可选的真 embedding 走 fastembed。
- **embedding 提供方可插拔**（`src/embedding_provider.py`）：本地（fastembed）与云端 HTTP 服务走同一个口子，**不内置任何一家的 SDK**（云端走各家通用的 `/v1/embeddings` 形状，stdlib urllib）；换服务商不改检索层。**API key 只走环境变量**，不写进 `mcp-config.json`、不进产出目录、不落任何状态文件。
- **检索路线是自己用户选的**：初始化流程里有一步专门问——三条路（零依赖／本地模型／云端服务）连同各自的**语料去向**念给他听，云端那条会把查询和被检索的内容发到第三方服务商。**没选过就不出货**（拦的是“没问过”，不是“没选云端”）。默认档仍是零依赖，语料不出本机。
- **门槛常数跟模型绑定，没量过就说没量过**：可靠命中的余弦门槛是一张按模型的实测标定表，表里没有的模型返回“未标定”，此时向量路只参与排序、不单独放行候选——照抄别的模型的数值会让“库里没有就说没有”无声失灵。
- **每个文件自带自检**：`python <文件名> --selftest`。
- **端到端冒烟**：`python src/e2e_smoke.py --selftest` 跑完从导入到检索的整条链。
- **检索融合**：BM25 词面 + 语义 + 关系图谱三路 RRF 融合。诚实标注：默认零依赖档下语义那一路（字符 bigram 余弦）跟词面路高度重合、几乎没有独立贡献（我们自己的回归集消融实测），实际是词面+图谱两路在干活；装 fastembed 走 `--embed` 后语义路才名副其实。`latent_search` 另接受一个可选 `queryVariant`：自然问法查不到时，由宿主模型补一种更具体的说法，服务器保留原查询并做一次受控 RRF 融合；原查询两票、改述一票，最终 topN 才加一次权重。⚠ 机制已用虚构夹具和真 MCP 调用验证；外部十道私有题没有上交，**不能写成原 5/10 已经提高到某个新分数**。
- **MCP 协议**：按官方规格 2025-06-18 实现；同时支持本地 stdio 与远程 Streamable HTTP（`--http`＋`--token`）。`--http` 收的是 `[HOST:]PORT`，**省略 HOST 只绑回环、别的机器连不到**；绑非回环时起动横幅会多打一行提醒——那条链路是裸 HTTP，token 与检索回来的记忆内容都是明文，推荐绑回环、公网那一跳交给反代管 TLS（**只提醒，不拦你起动**）。
- **按客户端的 `Accept` 给传输形态**：只认 SSE 响应体的客户端拿到单事件 SSE（`event: message` ＋ `data:`），其余拿 `application/json`（`Accept` 里两个都写、写 `*/*`、或没带这个头，都走 JSON）；**GET 会拿到一条只发心跳、永不发消息的空长流**——本服务没有服务器主动推送的场景，这条流存在的理由只有一个：有的客户端先发 GET 建长流，收到 405 之后不改用 POST，就一直等下去。不要它就加 `--no-sse-stream`（那样 GET 恒回 405）。长流同时最多 4 条。⚠ **这两条只有自检盖着、没有真机**：自检是真端口往返，量的是「服务端形态已具备」，**不是「哪个客户端因此接上了」**。
- **工具名带 `latent_` 前缀**：`latent_search` / `latent_session_start` / `latent_append` / `latent_correct` / `latent_thread_close`。前缀不是装饰——**通用名（`memory_search` 这类）可能跟宿主自带的同名工具撞上**，撞上之后服务照常连着、工具列表照常看得见、模型照常回话，只是调的不是这一份，**全程零报错**。**有一例外部实测支撑这条**：一位 Kelivo 用户在无前缀的旧版上连不上，**把工具名自定义之后就能正常用了**（外部自述，本项目未复现；⚠ 他改成了什么名字、客户端版本这些没记全，只当方向性证据——而且**他验的是他自己改的名，不是这一版的 `latent_` 前缀**）。⚠ **从无前缀的旧版本升上来的话，人格文件／`CLAUDE.md` 里写死的旧工具名要跟着改**（重新出货一次最省事），否则模型会去调一个不存在的工具。
- **被拒的请求在服务端留一行**：401／403／404／405／400／411／413／501 各说各的原因（含方法、路径、来源 IP），**排查不用猜是哪一种**；正常请求照旧不打日志。⚠ 405 有三种含义，那一行会说清是哪一种（客户端本来就只要 JSON／长流被 `--no-sse-stream` 关掉了／长流开满了）——**只有第一种不是故障**，另两种下不会回退的客户端会一直等。⚠ 那一行**不含 token、不含请求体**（那里面是你的问句和记忆正文），路径也剥掉了 query；被扫时有每分钟上限，**压掉多少条会明说**。

| **其它聊天端** | ⚠ **未实测、需确认 MCP 支持状态。**各家叫法不一（自定义 Connector／远程 MCP／集成），不能借用 ChatGPT、claude.ai、Grok 聊天端或 Grok Build 的成色 |
| Kelivo（闭源手机前端） | **实测可接 MCP**：原生 `--http` 直连走通（Kelivo 1.1.17 iOS ／ VPS Ubuntu ＋ Python 3.10.12；判据是端口上蹲的确认为 `python3` 不是 Node、POST 回的是 `application/json`）。⚠ **连不上先看绑定地址，不是协议**：省略 HOST 只绑回环，手机连不到。人格要手工导入 system prompt，容量不是阻塞项 |
| Operit（闭源手机前端） | **实测五工具可用，写回后跨新会话仍能检索命中**（Android 的 proot Ubuntu）。⚠ 它走的是「客户端在手机本机按 stdio 拉起」那条——**不用公网服务器、不用域名证书鉴权，语料根本不离开手机**；**别把闭源手机前端一概读成「必须有服务器」**，那只对拉不起 stdio 的客户端（如 iOS 上的 Kelivo）成立。人格不自动注入，要手工粘贴 |
| 自建前端（`--client generic`） | **出货档和注入契约有了，但我们没有验过任何一个自建前端**——注入那一半是你写的，契约五条成不成立只有你自己 diff 请求体才知道 |

**跑起来验过的操作系统与 Python**（上面那张表记的是客户端，这一格记的是环境；同一条规矩：**没列进来的就是没验过**）：

| 环境 | 验到什么 |
|---|---|
| Linux ／ Python 3.11 | `src/` 每个 `.py` 的 `--selftest` 全绿（判据是退出码 0，不看输出内容）；非交互走完 `inspect → extract → choose-sections → preview → route → ship` 整条初始化 |
| Windows ／ Python 3.12（win32） | 同上，另加三条只在 Windows 上才看得出来的：中文控制台（`chcp` 936）下 `--json` 那几步不崩；出货的 `mcp-config.json` 三个路径都是绝对路径（工作目录在别处、`--out` 给相对路径时也是）；问卷那几屏没有漏出 `{ta}` 这类占位符 |

**接入不确定时，先跑这三条**：不同客户端分别怎么接，见 [`docs/快速上手.md` §3c](docs/快速上手.md#3c-哪些客户端能接哪些不能以及聊天窗口那格的现状)；已经部署好、想确认它到底读到了什么，跑 `python src/mcp_server.py --doctor --corpus <你的语料目录>`——**只读**，打出读的绝对路径、进库多少块、时间范围、分层与时间戳来源分布，一眼看出是没跑通还是只是目录名不同；**客户端一直说连不上时，先看服务端终端上有没有「被拒 …」那一行**——有，说明包打到我们了，照那行给的原因修（路径、token、传输编码）；**一行都没有，说明包压根没到**，那是绑定地址／防火墙／端口映射那一类，别再在协议上找原因。
已知的诚实边界都写在代码的 docstring 里——哪些翻译器跟真实导出核对过、哪些还没有，哪些参数是经验值待调，都标着。
