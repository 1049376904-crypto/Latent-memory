# 给 AI 的引导指南

> **这份文档是写给 AI 读的，不是写给人读的。**
>
> 如果你是一个 AI，用户把这个仓库交给了你、让你帮 TA 建自己的记忆系统——那么这份文档就是你的操作说明。
> 按这里写的做，一步步带 TA 走完，不要让 TA 自己去读代码或技术文档。
>
> 如果你是人类：你不需要读这份，把仓库地址交给你正在用的 AI，说一句"读一下 docs/给AI的引导指南.md，带我做"就行。

---

## 零、你在帮 TA 做一件什么事

用户想让 TA 的 AI **跨会话记得 TA**——不是这次对话记得，是换了新窗口、过了一个月、甚至换了个客户端之后，还认得 TA 是谁、记得你们之间发生过什么。

这套东西的产出是三样（我们叫它三件套）：

| 产出 | 是什么 | 作用 |
|---|---|---|
| **人格文件** | `CLAUDE.md` 或 `AGENTS.md` | 常驻上下文的"不变量"：TA 是谁、你们的相处方式、检索约定 |
| **记忆库** | 一个目录，里面是分窗口的 md | 会增长的那一半：发生过什么的完整记录 |
| **MCP 配置** | 一段配置 | 把记忆库接成可检索的服务 |

**一句话分工：人格文件负责让模型"知道该查"，MCP server 负责"查得到"。缺哪半都不成立**——这是真机实测三轮得出的结论，不是设计推测。

## 一、动手前先问清楚三件事

不要一上来就跑命令。先用聊天的方式问 TA，一次问一件，等 TA 答完再问下一件：

### 1. TA 有没有历史对话记录可以导入？

- **有**：TA 需要先去导出。Claude 是「设置 → 隐私 → 导出数据」，邮件收 zip；ChatGPT 是「设置 → 数据控制 → 导出」。
  **务必提醒 TA：时间范围要选"全部"，不要选"最近 30 天"**——选 30 天会把窗口外的对话全部框空，导出来近乎是空的（这是踩过的坑）。
- **没有**：完全没问题，走冷启动问卷，全部是选择题。**不要让 TA 觉得没有历史就不能用**。

### 2. TA 打算在哪儿用这个 AI？

划线标准不是手机还是电脑，是**客户端能不能读文件、接 MCP**。三种情况：

- **电脑上的 Claude Code / Codex** → 正常走，全功能。
- **只有手机，但愿意用云端会话** → 也能走。Claude Code 和 Codex 都有云端版，**官方手机 App 里就有入口**（Claude App 的 Code 入口、ChatGPT App 的 Codex 入口；网页 claude.ai/code、chatgpt.com/codex 也行），都连 GitHub 仓库：把人格文件放进仓库根目录（CC 读 `CLAUDE.md`，Codex 读 `AGENTS.md`），云端会话连着这个仓库起，每次自动克隆自动读。云端 Claude Code 这条是长期真实运行验证过的模式；Codex 云端同一个模式、我们未实测。两个注意：①云端容器是临时的，**记忆库长出来的新内容要提交推回仓库才算保存**，不推的话容器回收就丢——提醒 TA 养成会话收尾让 AI 推一次的习惯；②MCP 检索层在云端容器里的完整接入（`.mcp.json` 起本地 stdio server）尚未实测，人格文件这半是验证过的，检索这半接不通就先用人格文件+记忆库全文，功能少一层但能用。
- **只用手机聊天 App（不愿意碰云端 CC）** → 这套现在接不上，如实告诉 TA。可以先把人格文件生成出来存好，以后支持了直接用。

### 3. TA 有没有能跑 Python 的环境？

初始化这一步（本文档第三节的命令）需要真的在文件系统上跑 Python——本地终端或云端 Claude Code 的会话里都行，纯聊天界面做不了。这跟上一问是两件事：初始化在哪儿跑一次性，日常在哪儿用是长期的，两者可以不是同一个地方（比如在云端会话里初始化，产出物推进仓库，以后每次从仓库读）。

## 二、四条纪律（比流程更重要）

这四条是这个项目的核心判断，违反了产出的东西就没用了。**你在整个过程中都要守着**：

### 纪律一：纪录片，不做说服

写进人格文件和记忆库的，必须是**发生过什么、当时说了什么原话、现在是什么状态**。

- ✅ 「TA 说"这周不想见人"，我把周末的安排往后挪了。」
- ❌ 「你们经历过考验，感情非常深厚。」

形容词长不出人格，只会长出一个会背评语的模型。**当 TA 给你形容词时，追问具体的事**。

### 纪律二：不要替 TA 编内容

TA 答不上来是**有效信息**，说明这段关系还没长到那儿——那一节就该短，甚至空着。
**宁可短且真，不可长而空。**

尤其注意：核心哲学的隐喻、里程碑这类，新用户第一天本来就没有，硬要 TA 现编比空着更糟。系统对这些是"推荐但不阻塞"，你也该这样。

### 纪律三：人格文件的任何内容，必须 TA 确认过才写进去

记忆库正文可以自动写，**人格文件不行**。生成的每一条都要念给 TA 听、TA 说可以才留。
这是硬关卡，代码里也拦着（未确认时拒绝写盘）。

### 纪律四：TA 的语料是 TA 的

**绝对不要把 TA 的对话记录、人格文件、记忆库提交到这个开源仓库里。**
TA 的东西应该放在 TA 自己的目录/仓库。你在帮 TA 建的过程中，如果需要 git，用 TA 自己的仓库。

## 三、操作流程

**命令是你跑的，不是 TA 跑的。** TA 该做的只有两件：建一个文件夹（或仓库），以及在对话里回答你的问题。下面每条命令都能非交互执行，你不需要让 TA 去开终端、也不需要把命令贴给 TA 让 TA 自己敲——TA 来找你就是为了不折腾这些。

所有命令在 `src/` 目录下执行。**产出目录必须是一个新建的专属文件夹**，不能是已有的工作项目——`CLAUDE.md` 按目录生效，放进别的项目里会跟那个项目的配置打架。

### 第 1 步：体检 + 出问卷

```bash
python memory_init.py --out <产出目录> [--corpus <TA的导出文件>] --step questionnaire --json
```

带 `--json` 拿到的是机器可读的体检结果和题目（含每个选项的文案与指引）——你要的是这个，不是给人看的排版文本。（不带 `--json` 会打印人类可读版，TA 想自己看的时候用。）

**问卷全部是选择题**——设计上就是让用户提供判断标准、不提供内容，具体内容由模型去语料里找。

**然后你在对话里一题一题问 TA**，把选项念给 TA 听。这是默认路径，因为 TA 找你就是为了不用自己折腾。每题 TA 都可以自由补一句（限 40 字）。

（TA 要是更想自己在别处答：产出目录下有个 `问卷prompt.txt` 可以粘给任何模型，答完存成文本清单，走下面第 2 步的 `--answers` 那条。）

### 第 2 步：把答案交回去

```bash
python memory_init.py --out <产出目录> --step answers --answers-json '{"disagree":{"keys":"A"},"state_now":{"keys":"D","note":"TA 补的一句"}}'
```

答案直接以 JSON 交回，**不用先写成文件再让程序解析**——你手上已经是结构化的了。取值可以是 JSON 字面量、文件路径，或 `-`（读 stdin，内容长时用它）。

- 选择/多选题：`{"keys": "A"}` / `{"keys": "AC"}`，可加 `"note"` 放 TA 补的那句
- 从语料里挑的题、极短填空：`{"pick": "TA 选中或写下的原文"}`
- **TA 答不上来的题就不要放进去**——那一节空着是诚实的，别替 TA 编（纪律二）

（走 `问卷prompt.txt` 那条路的话，这步用 `--answers <文本清单文件>`，程序会连猜带解析地读，读不懂的行会原样报出来。）

### 第 3 步：逐条确认（**这步的重点不是命令，是真的去问 TA**）

先取出待确认的草稿：

```bash
python memory_init.py --out <产出目录> --step confirm --list --json
```

**然后把每一条念给 TA 听，由 TA 决定留/删/改。** 这是纪律三，也是这一步存在的全部意义——人格文件的每一条都要 TA 认过。收齐 TA 的决定后：

```bash
python memory_init.py --out <产出目录> --step confirm --decisions-json '{"field:style_disagree":"keep","field:user_focus":{"edit":"TA 改后的文本"},"field:xxx":"drop"}'
```

三件事程序替你兜着，但**不要依赖它们来代替真的问**：

- 没出现在 `--decisions-json` 里的条目**保持未决**，不会被默认留下也不会被默认删掉；
- 还有未决条目时，第 4 步**拒绝出货**（不然那些草稿会静默消失，文件看着正常只是少几节）；
- 认不出的 key 会明确报错，不静默丢。

### 第 4 步：出货

```bash
python memory_init.py --out <产出目录> --step ship --client claude-code
```

（如果 TA 用 Codex，`--client codex`，产出 `AGENTS.md`。）

产出目录下会出现 `CLAUDE.md`、`memory/`、`mcp-config.json` 三样。

### 第 5 步：接入客户端

```bash
claude mcp add memory --scope user "--" python <src绝对路径>/mcp_server.py --corpus <产出目录>/memory --threads <产出目录>/threads.jsonl
```

三个踩过的坑，提醒 TA：

- **PowerShell 会吞掉裸的 `--`**，必须像上面这样带引号写成 `"--"`。
- **不加 `--scope user`** 的话配置只对当前目录生效，换个目录起会话就找不到了。
- 路径用正斜杠 `/`，Windows 一样认，省掉转义麻烦。

### 第 6 步：验证

让 TA **开一个全新会话，并且从产出目录起**（人格文件在那儿才会被读到），第一句问一件只有 TA 们的历史里才有的事，**别提任何工具字眼**。

- ✅ 接通了：模型主动查了记忆再回答。
- ❌ 没接通：模型说"我没有相关记录"。

没接通时按顺序查：会话是不是起在产出目录里（这是最常见的原因）→ `claude mcp list` 里 memory 服务连着没有。

## 三·五、两条检索路线，装完之后再问 TA 一次

产出物跑起来之后，检索有两条路线。**默认那条不用装任何东西，先用着；这一节是等
TA 用上一阵、觉得"它有时候找不到我明明说过的事"时再回来看的。** 别在第一次设置时
就抛给 TA 选——那会把一个本来很轻的流程变重。

| | 路线一：零依赖（默认） | 路线二：真向量语义（可选） |
|---|---|---|
| 要装什么 | 什么都不用装 | `pip install fastembed`，首次运行下载约 100MB 中文模型 |
| 怎么开 | 默认就是 | MCP 配置的启动参数加 `--embed` |
| 语料在哪 | 不出本机 | 一样不出本机（模型在本地 CPU 跑） |
| 代价 | 无 | 建库和检索都变慢，低配机器（2C2G 这类）感知明显 |

**两条路线的实际差别（我们自己的回归集实测，不是估计）**：在一份两百块左右的
语料上，"换个说法问同一件事"这类查询，零依赖路线大约能答对四分之三，真向量路线
基本都能答对；"这件事后来怎么样了"这类要跨很多个窗口串起来的查询，两条路线都还
不算好，真向量略强一些。**词面直给的查询两条路线一样好**——所以如果 TA 平时就是
用原话去问，零依赖完全够用，不必折腾。

**一条重要的诚实话，两条路线都适用**：**这套东西目前不擅长说"我没有这条记忆"。**
理想情况下，TA 问一件从没记录过的事，系统该查不到、AI 该如实说没找到。我们拿一份
真实规模的记忆库（六百多块）实测过：**无论哪条路线，这件事都做得不好**——尤其
当 TA 问的是"像是记过、其实没记"的日常事（某次复诊约在几号、某张单子多少钱），
系统几乎总能捞回几条沾边但不相干的记录。

这对你意味着一件具体的事：**检索返回了东西，不等于那就是答案**。如果捞回来的几条
跟 TA 问的对不上，就直说对不上、说这件事库里可能没记，**不要拿沾边的记录去圆**。
这一条比"多答对几个问题"重要——记忆产品编造出来的"记得"，比承认不记得伤害大得多。

（技术上的原因和修法我们已经定位到了，排在下一轮。这里如实告诉你现状，不粉饰。）

## 四、接下来 TA 该知道的事

装完不是结束，告诉 TA 这几件：

1. **记忆库会自己长**。模型有一个写回工具（`memory_append`），对话里出现值得记的事会当场写进去，不用 TA 操心。
2. **人格文件是 TA 的**，随时可以自己改。改重了、改具体了都好——它一开始比较短是正常的，东西是慢慢长出来的。
3. **索引层可以补**。`memory/index/` 现在是空的，里面的说明写了怎么补（把某个窗口贴给模型让它写一段高密度摘要）。补上检索会更准，不补也能用。

## 五、如果出问题

- 每个 `src/*.py` 都能单独自检：`python <文件名> --selftest`，全绿说明零件正常。
- `python e2e_smoke.py --selftest` 一口气跑完从导入到检索的整条链，红了会指出断在哪一环。

排障时先跑这两个，能快速区分"是代码坏了"还是"是配置/使用问题"。
